# Придумать своего бота

## Когда нужен новый бот

Новый бот нужен не на каждую задачу. Он нужен, когда у дела есть свои источники, своё расписание
или свои доступы.

Пример: «Каждое утро собирать курс валют с двух сайтов». Тут есть расписание и свои источники —
это дело для отдельного бота.

## Когда хватит просьбы

Разовую задачу проще попросить у бота, который уже есть. Новый бот для неё — лишняя строчка в
списке.

Пример: «Переведи это письмо на английский». Просто попроси главного бота.

## Три вопроса для проверки

Сомневаешься — задай делу три вопроса. Оно повторяется по расписанию? Берёт данные из своих мест?
Ему нужен свой вход в сервис? Есть хоть одно «да» — пора делать бота.

Пример: «Каждый понедельник присылать мне план недели из календаря». Есть расписание и свой доступ
к календарю — нужен бот.

## Бот одной фразой

Опиши бота одной фразой: что он делает и для чего. Подробности Bot Maker уточнит сам.

Пример: «Бот, который пишет короткие вежливые ответы на сообщения клиентов, чтобы я отвечал
быстрее».

## Границы бота

У хорошего бота есть список того, чего он никогда не делает. Особенно важно про всё, что уходит
наружу: письма, оплаты, публикации.

Пример: «Ответы только готовит. Сам ничего не отправляет — отправляю я».

## Пароли — не в описание

Пароли, коды и ключи не пишут ни в описание бота, ни в чат. Для входа в сервисы есть подключения и
хранилище паролей в приложении: там пароль под защитой, а бот входит, не видя его.

Пример: боту нужна твоя почта. Ты подключаешь почту в приложении и сам входишь в неё. Бот работает
с почтой, а пароля так и не видит.
